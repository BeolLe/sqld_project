# 조인 과정 실행 애니메이션 설계

- 날짜: 2026-09-13
- 대상: 개념학습 `sb-join`(조인), `sb-sjoin`(표준 조인)
- 상태: 승인됨 (기존 컨벤션에 맞춰 수정)

## 배경

조인 단원에도 윈도우 함수 단원처럼 실행 과정을 재생하는 애니메이션을 붙인다.

처음 승인한 설계는 `QueryViz`가 원본 테이블 1개만 다룬다는 전제에서 조인 전용 노드(`joinviz`)와 컴포넌트를 새로 만드는 안이었다. 같은 날 `db9f921`에서 `QueryViz`에 여러 원본과 단계별 결과를 재생하는 `staged` 종류가 추가되어 9개 단원에 19번 적용됐다. 전용 컴포넌트를 따로 만들면 같은 역할의 재생기가 둘로 갈라지므로 **기존 `staged` 컨벤션을 그대로 따른다.** 컴포넌트와 타입은 바꾸지 않는다.

## 결정 사항

| 항목 | 결정 | 근거 |
| --- | --- | --- |
| 방식 | 단원 파일에 `kind: 'viz'` + `spec.kind: 'staged'`로 장면을 직접 적는다 | 기존 19개 사용례와 같은 방식 |
| 범위 | EQUI · Non EQUI · CROSS · OUTER 4개 | 행을 맞추는 동작이 다른 것만. NATURAL·USING은 EQUI 과정과 같다는 참조 한 줄 |
| 장면 수 | 애니메이션마다 3~4장면 | 기존 18개가 2~4장면이고 3장면이 10개 |
| 비교 과정 | 한 쌍씩 비교하는 과정은 장면을 늘리지 않고 설명 글에 담는다 | `staged`에는 원본 행 강조가 없고 장면 수를 짧게 유지하는 컨벤션 |
| OUTER 전환 | 장면마다 결과 라벨을 바꿔 INNER → LEFT → RIGHT → FULL을 한 애니메이션에서 보여준다 | 전환 버튼이 없는 컨벤션. 서브쿼리 단원도 장면마다 결과 라벨이 바뀐다 |
| 정적 표 | 삭제하지 않고 애니메이션만 추가한다 | 기존 단원에 애니메이션을 넣을 때 정적 내용을 지우지 않았다. 복습 빈칸도 보존된다 |
| 데이터 이름 | 한글(사원·부서·급여등급) | 조인 단원 본문과 함정이 최지원·박민수·인사팀을 직접 가리킨다. 단원 안에서 데이터를 일치시킨다 |
| NULL | 칸 안에 문자열 `'NULL'` | `VizCell`이 `string \| number`이고 서브쿼리·WHERE 단원도 같은 표기 |
| 문구 | 설명은 `① … ② …`, 중간 결과 라벨 `현재 결과`, 마지막 `최종 결과`. 긴 줄표는 쓰지 않는다 | 기존 사용례의 대표 형식과 개념노트 문체 규칙 |

기각한 안
- 전용 `joinviz` 컴포넌트: 재생기가 둘로 갈라진다
- `staged`에 행 강조·전환 버튼 추가: 다른 세션이 막 만든 공용 컴포넌트를 확장해야 하고, 사용자가 기존 컨벤션을 따르기로 했다

## 애니메이션 명세

### 1. EQUI JOIN · 조인 2절 (정적 매칭 표 다음)

- 쿼리: `SELECT 사원.사원명, 부서.부서명 FROM 사원, 부서 WHERE 사원.부서번호 = 부서.부서번호`
- 원본: 사원(김철수 10, 이영희 20, 박민수 10, 최지원 30) · 부서(10 개발팀, 20 영업팀, 40 인사팀)

| 장면 | 설명 | 결과 |
| --- | --- | --- |
| ① | 김철수(10)를 부서번호 10·20·40과 차례로 비교해 10 개발팀과 짝을 찾는다 | 1행 |
| ② | 이영희(20)는 영업팀, 박민수(10)는 개발팀과 짝이 된다 | 3행 |
| ③ | 최지원(30)은 같은 부서번호가 없어 제외된다 | 최종 3행 |

### 2. Non EQUI JOIN · 조인 4절 (결과 표 다음)

- 쿼리: `SELECT E.사원명, E.급여, G.등급 FROM 사원 E, 급여등급 G WHERE E.급여 BETWEEN G.최저급여 AND G.최고급여`
- 원본: 사원(김철수 3500, 이영희 2800, 박민수 5200) · 급여등급(1: 0~2999, 2: 3000~4999, 3: 5000~9999)

| 장면 | 설명 | 결과 |
| --- | --- | --- |
| ① | 김철수(3500)를 등급 구간과 차례로 비교해 3000~4999인 2등급을 찾는다 | 1행 |
| ② | 이영희(2800)는 0~2999 구간이라 1등급이다 | 2행 |
| ③ | 박민수(5200)는 5000~9999 구간이라 3등급이다 | 최종 3행 |

### 3. CROSS JOIN · 표준 조인 4절 (Oracle 대응 표 다음)

- 쿼리: `SELECT 사원명, 부서명 FROM 사원 CROSS JOIN 부서`
- 원본: 사원(김철수, 이영희, 박민수) · 부서(개발팀, 영업팀, 인사팀)

| 장면 | 설명 | 결과 |
| --- | --- | --- |
| ① | 김철수가 부서 3개와 모두 조합된다 | 3행 |
| ② | 이영희도 부서 3개와 모두 조합된다 | 6행 |
| ③ | 박민수까지 조합하면 3 × 3 = 9행 | 최종 9행 |

### 4. OUTER JOIN · 표준 조인 5절 (결과 행 수 표 다음)

- 쿼리: `SELECT 사원명, 부서명 FROM 사원 [조인 종류] 부서 ON 사원.부서번호 = 부서.부서번호`
- 원본: 사원(김철수 10, 이영희 20, 박민수 NULL) · 부서(10 개발팀, 20 영업팀, 40 인사팀)

| 장면 | 결과 라벨 | 결과 |
| --- | --- | --- |
| ① | INNER JOIN 결과 | 김철수 개발팀, 이영희 영업팀 (2행) |
| ② | LEFT OUTER JOIN 결과 | 위 2행 + 박민수 NULL (3행) |
| ③ | RIGHT OUTER JOIN 결과 | 위 2행 + NULL 인사팀 (3행) |
| ④ | FULL OUTER JOIN 결과 | 위 2행 + 박민수 NULL + NULL 인사팀 (4행) |

### 5. NATURAL·USING · 표준 조인 3절

애니메이션 없이 `※ NATURAL JOIN과 USING이 짝을 찾는 과정은 조인 단원 EQUI JOIN의 실행 과정과 같다.` 한 줄을 둔다.

## 검증

1. 장면마다 결과 행이 SQL 규칙과 맞는지 파이썬으로 조인을 직접 계산해 단원 파일의 `steps` 값과 대조한다. 결과 행 수는 EQUI 3 · Non EQUI 3 · CROSS 9 · INNER 2 · LEFT 3 · RIGHT 3 · FULL 4
2. `tsc --noEmit` · `npm run build` · `npm run check:query-viz` 통과
3. 브라우저에서 4개 애니메이션 재생, 복습 모드 빈칸 수(조인 11 · 표준 조인 14) 유지
4. 개념노트 문체 검사: 긴 줄표 0, 볼드 안 빈칸 0

## 제약

`staged`는 사람이 장면을 직접 적는 방식이라 결과 값을 잘못 적어도 컴포넌트가 잡지 못한다. 검증 1번의 파이썬 대조가 그 역할을 한다. 또한 개념노트 저작 도구로 두 단원을 다시 저장하면 `viz` 노드가 사라진다. 윈도우 함수·관계 단원과 같은 기존 제약이다.
