01개요

배경회의 결정 사항: ADsP를 먼저 개발하고 그다음 모바일 앱을 추가한다. SQLD와 ADsP는 같은 사이트에서 쓴다.
이 문서의 목적사이트 통합의 전체 틀(정보 구조, 헤더, 시험 전환 방식, 화면 목록, URL)을 잡고 회의에서 A안·B안 중 하나를 고른다.
범위웹 반응형 화면. 모바일 앱은 이번 범위 밖이며, 앱으로 옮기기 쉬운지만 비교 항목에 넣었다.
범위 밖시각 디자인(색, 일러스트), 세부 문구, ADsP 문제 콘텐츠, 결제 상품 구성
메인→ 시험 선택 (SQLD / ADsP)→ 모의고사 · 개념 학습 · 무한풀이→ 응시 · 결과 · 해설→ 학습현황

A안 · 시험을 먼저 고른다

/sqld/exams · /adsp/exams

헤더에 [SQLD | ADsP] 전환기를 두고, 고른 시험에 따라 메뉴와 콘텐츠 전체가 바뀝니다. 사이트 안에 시험별 공간이 두 개 있는 구조입니다.

  • 지금 어떤 시험을 공부 중인지 항상 분명함
  • 기존 페이지를 거의 그대로 재사용 (URL 앞에 시험만 붙임)
  • 모바일 앱의 "시험 선택 → 하단 탭" 구조로 옮기기 쉬움
  • 두 시험을 오가려면 전환기를 한 번 눌러야 함

B안 · 기능을 먼저 고른다

/exams?exam=adsp

메뉴는 지금처럼 기능별로 하나만 두고, 각 페이지 안에서 시험 탭이나 필터로 나눕니다. 시험은 "내 관심 시험"으로 기본 필터만 정해 둡니다.

  • 두 시험을 함께 준비하는 사용자가 한눈에 비교하기 쉬움
  • URL과 메뉴 구조가 지금과 같아 기존 링크가 그대로 유지
  • 모든 목록 페이지에 필터와 시험 뱃지를 새로 넣어야 함
  • SQL 실습처럼 한 시험에만 있는 메뉴가 어색해짐

05실제 디자인으로 보는 A안 · B안 데모

지금 SolSQLD 화면(target/main)의 마크업과 Tailwind 클래스를 그대로 옮긴 미러 데모입니다. 헤더, 메인, 시험 일정 카드, 모의고사 목록, A4 응시 화면(5문항씩 10페이지, 타이머, 메모장, 제출·이탈 확인 창), 결과, 무한풀이 3단계 선택, 개념 학습 목차와 단원(빈칸 복습), 학습현황, SQL 실습 목록까지 실제와 같은 흐름으로 눌러볼 수 있습니다.
