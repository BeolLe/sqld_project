## 1. 배경

### 왜 필요한가

현재 SolSQLD는 **문제를 푸는 곳**이다. 모의고사 10세트(약 500문항)와 SQL 실습 60문항이 있지만, **학습할 곳이 없다.** 틀린 문제의 해설을 읽는 것 외에는 개념을 익힐 경로가 없어서, 사용자는 개념 학습은 외부(요약본 PDF, 유튜브, 책)에서 하고 우리 사이트에는 문제 풀 때만 들어온다.

교육 탭은 이 이탈을 막고 **학습 → 문제풀이 → 오답 → 재학습** 순환을 사이트 안에서 완결시키는 것이 목적이다.

### 시장 현황 (조사 결과)

SQLD 요약 자료는 **이미 무료로 포화 상태**다.

- 위키북스 "급한 사람을 위한 SQLD 핵심정리노트" PDF 무료 배포
- GitHub, Velog, Scribd에 요약본 다수
- 70페이지 분량 핵심요약 굿노트 유통

수험생의 전형적 패턴은 이렇다. 노랭이(`SQL 자격검정 실전문제`) 문제 풀이가 주력이고, **요약본은 시험 직전 최종 암기용**으로 쓴다. 2주 단기합격이 흔하다.

> **따라서 "요약 PDF 제공"만으로는 차별화되지 않는다.**
> 차별점은 요약본을 **읽고 끝내지 않게** 만드는 데 있다. 읽은 직후 같은 내용을 빈칸으로 다시 채우게 하면 능동 회상(active recall)이 강제되어 정착률이 올라간다. PDF는 이걸 못 한다.

### 기존 콘텐츠 현황

| 자산 | 수량 | 경로 |
|---|---|---|
| 모의고사 | 10세트 / 약 500문항 | `frontend/src/data/exams/` |
| SQL 실습 | 60문항 (easy·medium·hard 각 20) | `frontend/src/data/practice/` |
| 연습 테이블 | 3종 (emp, order, student) | `frontend/src/data/tables/` |

기존 모의고사 카테고리 분포에서 얇은 영역: `GROUP BY` 8 · `ORDER BY` 4 · `Top N 쿼리` 4.

## 2. 공식 출제범위 (dataq.or.kr)

| 과목 | 문항 | 배점 | 세부항목 |
|---|---|---|---|
| 1. 데이터 모델링의 이해 | 10 | 20점 | 10개 |
| 2. SQL 기본 및 활용 | 40 | 80점 | 20개 |

합격 기준은 **총점 60점 이상**이되 **과목별 40% 미만이면 과락**이다. 1과목은 10문항뿐이라 4문항 미만이면 2과목 성적과 무관하게 불합격한다. 배점은 2과목이 크지만, **1과목을 버리면 안 된다**는 점이 콘텐츠 우선순위에 반영되어야 한다.

## 4. 학습 흐름

```
교육 탭 진입 (/learn)
  │
  ├─ 단원 목록 (10개, 과목별 그룹)
  │    진도 표시: 미학습 / 읽는 중 / 복습 완료
  │
  ▼
단원 상세 (/learn/:unitId)
  │
  ① 개념 노트          ← 메인 콘텐츠. 단락별 핵심, A4 1~2장 분량
  │   · 단락 3~6개
  │   · 표·코드블록 적극 활용, 산문 최소화
  │   · 끝까지 읽으면 하단에 복습 진입 CTA 노출
  │
  ▼
  ② 빈칸 복습          ← 같은 내용이 빈칸으로 재등장
  │   · 본문 인라인 입력 방식
  │   · 입력 즉시 채점, 오타·동의어 허용
  │   · 전부 맞히면 단원 완료 처리
  │
  ▼
  ③ 개념 노트 다운로드  ← 시험 직전 최종 암기용
```

**핵심 설계 원칙:** 빈칸은 부가 기능이 아니라 노트를 "읽고 끝내지 않게" 만드는 장치다. 그러나 **메인 콘텐츠는 개념 노트**이며, 빈칸은 그 파생물이다. 노트 없이 빈칸만 존재할 수 없다.

## 5. 커리큘럼 구조

**공식 출제범위의 3단 구조를 그대로 따른다.** 임의로 묶거나 쪼개지 않는다 — 수험생이 다른 교재·기출과 대조할 때 항목명이 일치해야 하고, 출제범위가 개정되면 그 단위로 갱신해야 하기 때문이다.

```
과목 (2)  →  주요항목 (5)  →  세부항목 (30)  ← 학습 단위
```

`세부항목` 하나가 곧 개념 노트 한 편이며, URL은 `/learn/:unitId` 로 대응한다.

### 1과목 · 데이터 모델링의 이해 (10문항 / 20점)

| 주요항목 | 세부항목 |
|---|---|
| 데이터 모델링의 이해 | 데이터모델의 이해 · **엔터티** · **속성** · **관계** · **식별자** |
| 데이터 모델과 SQL | **정규화** · 관계와 조인의 이해 · 모델이 표현하는 트랜잭션의 이해 · **Null 속성의 이해** · 본질식별자 vs 인조식별자 |

### 2과목 · SQL 기본 및 활용 (40문항 / 80점)

| 주요항목 | 세부항목 |
|---|---|
| SQL 기본 | 관계형 데이터베이스 개요 · **SELECT 문** · **함수** · **WHERE 절** · **GROUP BY, HAVING 절** · ORDER BY 절 · **조인** · **표준 조인** |
| SQL 활용 | **서브쿼리** · 집합 연산자 · 그룹 함수 · **윈도우 함수** · Top N 쿼리 · 계층형 질의와 셀프 조인 · PIVOT 절과 UNPIVOT 절 · 정규 표현식 |
| 관리 구문 | **DML** · TCL · **DDL** · DCL |

### 제작 우선순위

**굵게 표시된 16개 항목이 1차 제작 대상**이다. 출제 빈도와 과락 방지를 기준으로 골랐다. 구조는 처음부터 30개를 전부 노출하되, 콘텐츠가 없는 항목은 `미학습` 상태로 두고 순차적으로 채운다.

전체를 한 번에 쓰려면 몇 주가 걸리므로, 목차만 먼저 완성해 두고 콘텐츠를 점진적으로 붙이는 방식이다. 사용자는 전체 학습 지도를 먼저 보게 되고, 제작 진행 상황이 그대로 진도 UI가 된다.

## 6. 콘텐츠 제작 규격 (사람이 직접 작성)

### 분량 기준

| 단위 | 분량 |
|---|---|
| 세부항목 1개 | A4 1~2장 (약 800~1,500자) |
| 단락 | 3~6개 |
| 단락당 빈칸 | 2~4개 |
| 세부항목당 빈칸 | 8~20개 |

| 단계 | 항목 수 | 노트 분량 | 빈칸 |
|---|---|---|---|
| 1차 | 16개 | 16~32장 | 130~320개 |
| 전체 | 30개 | 30~60장 | 240~600개 |

세부항목마다 분량 편차가 크다. `DCL`이나 `ORDER BY 절`은 1장도 안 되고, `함수`나 `조인`은 2장을 넘길 수 있다. 1~2장은 상한 가이드이지 채워야 할 하한이 아니다 — **짧게 끝나는 항목은 짧게 끝내는 것이 치트시트의 취지에 맞다.**

### 작성 원칙

1. **산문 금지.** 표, 비교 대조, 코드블록, 불릿으로 쓴다. 문장은 정의와 함정 설명에만 쓴다.
2. **함정 중심.** SQLD는 헷갈리게 내는 시험이다. `TRUNCATE vs DELETE`, `NVL vs NVL2`, `HAVING vs WHERE`처럼 혼동 쌍을 표로 대조한다.
3. **빈칸은 핵심어에만.** 조사나 서술어에 뚫지 않는다. 그 단어를 모르면 문제를 틀리는 단어에만 뚫는다.
4. **동의어를 미리 등록.** `롤백 불가` / `불가` / `안됨` 처럼 표기 흔들림을 `accepts`에 넣는다. 이걸 안 하면 맞는 답을 틀렸다고 하는 최악의 경험이 나온다.

### 데이터 구조 (제안)

```ts
// frontend/src/data/learn/types.ts
interface LearnUnit {
  id: string;              // 'sb-sjoin'
  subject: 1 | 2;          // 과목
  group: string;           // 주요항목 — 'SQL 기본'
  order: number;           // 과목 전체 통합 순번 (공식 출제범위 순서)
  title: string;           // 세부항목명 — 공식 표기 그대로 사용할 것
  /** 단원 상세의 meta 설명용. 목록 카드에는 노출하지 않는다. */
  summary: string;
  estimatedMin: number;
  priority1: boolean;      // 1차 제작 대상 여부
  /** 미제작 항목은 빈 배열. 목록에는 노출하되 '미학습'으로 표시한다. */
  blocks: LearnBlock[];
}

interface LearnBlock {
  id: string;
  heading: string;
  /** 본문 마크다운. 빈칸은 {{b1}} 토큰으로 표기 */
  body: string;
  blanks: Blank[];
}

interface Blank {
  id: string;              // 'b1'
  answer: string;          // 정답(표시용)
  accepts: string[];       // 정답 인정 목록 (소문자·공백 무시 비교)
  hint?: string;
}
```

콘텐츠 작성자는 `frontend/src/data/learn/units/*.ts` 에 위 구조로 채워 넣는다. 마크다운 본문에 `{{b1}}` 토큰을 심고 `blanks` 배열에 정답을 정의하는 방식이라, **노트를 먼저 쓰고 나중에 빈칸을 뚫을 수 있다.**

## 7. 기능 요구사항

### FR-1 단원 목록 (`/learn`)
- 과목별 그룹, 카드 그리드
- 각 카드는 **제목 · 진도 배지 · 예상 시간**만 노출한다. 요약문과 빈칸 개수는 넣지 않는다 — 10개 카드가 한 화면에 깔리는 구조라 카드당 텍스트가 늘면 목차로서의 훑어보기 기능을 잃는다.
- 진도: `미학습` / `읽는 중` / `복습 완료`
- 1과목 헤더에 과락 경고를 표기한다 (배점이 20점이라 사용자가 경시하기 쉬우나 실제 탈락 원인이 된다)

### FR-2 개념 노트 (`/learn/:unitId`)
- 단락 단위 렌더링, 표·코드블록 지원
- 읽기 진행률 표시
- 끝까지 도달 시 "빈칸으로 복습하기" CTA 활성화

### FR-3 빈칸 복습
- 본문 인라인 입력
- 입력 후 blur 또는 Enter 시 즉시 채점
- 정답: 초록 테두리 + 체크 / 오답: 빨강 + 정답 표시
- 대소문자·앞뒤 공백 무시, `accepts` 목록 대조
- 하단에 점수 및 "틀린 것만 다시" 버튼

### FR-4 다운로드
- **개념 노트(완성본)** PDF 다운로드
- 인쇄 최적화 CSS (배경 제거, 페이지 나눔)
- 로그인 없이 허용 (초기 유입 우선)

### FR-5 진도 저장
- 로그인 시 서버 저장, 비로그인 시 localStorage
- 단원별 상태 + 빈칸 정답률

## 9. 제작 계획

| 단계 | 내용 | 선행 조건 |
|---|---|---|
| 0 | 시안 확정 (A/B/C) | 데모 검토 |
| 1 | 데이터 구조 및 타입 정의, 라우팅 추가 | 시안 확정 |
| 2 | 파일럿 1개 단원 작성 (`관리 구문` 권장) | 구조 확정 |
| 3 | 파일럿로 UI 검증 및 조정 | 2 완료 |
| 4 | 나머지 9개 단원 작성 | 3 완료 |
| 5 | 다운로드 · 진도 저장 · 이벤트 로그 | 병행 가능 |

**파일럿으로 `관리 구문(DML·DDL·TCL·DCL)`을 권장하는 이유:** 암기 위주라 치트시트 형식이 가장 잘 맞고, 표 대조가 많아 빈칸 뚫기 좋으며, 분량이 예측 가능하다. 여기서 형식이 검증되면 나머지는 같은 틀로 찍어낼 수 있다.
